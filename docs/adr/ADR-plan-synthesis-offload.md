## 背景与问题

### ① 问题陈述

`plan` 侧的多节点协作（`ADR-plan-multi-session-collaboration`）在**dispatch / join** 阶段不要求父读子产出全文（子结果只回「指针 + 2–4 行摘要」）。但**合成**阶段必须：父要把 N 个节点的结论收敛成一份 topic 级答案。⇒ **父必须吸收 N 份子产出的全文。**

实测（`build-worker-design` 场景，7 节点）：子产出合计 **244,703 B**；父吸收它们后**根会话上下文增量 +114,842 tokens**；父写出的合成稿 **23,649 B**（**收敛比 ≈ 1:10**）。⇒ **合成是「收敛」而非「拼接」，而收敛的那一步目前落在用户面对的会话上。**

### ② 为什么不能靠既有通道

- **既有通道都不提供「聚合」这一步**：`delegate` 是工程实施派发（单槽、写隔离、`scope` 差集）；`plan-topics` 协作区提供 fork/join/fence/收敛，但**没有「把 N 份产物收敛成一份」的载体** —— 父只能自己做。
- **父自己做 ⇒ 合成质量无机械保证**：`progress`/`status` 是**从磁盘派生**的（派生而非自述），而合成稿是**自述**产物 ⇒ 父的判断、裁剪、遗漏**都不留痕**；换根会话后无法重建「父当时怎么合的」。

### ③ 本篇要解决的真问题

1. 把**收敛动作**从「用户面对的根会话」移到**一个可追溯、可复现、可被 judge 的载体**上；
2. 在不削弱任何既有写隔离不变式、不新增派发通道、不新增**机制面**判据的前提下做到；
3. 并把「合成质量」变成**可判定的**（而非散文）。

## 决策

### D1 合成进入 DAG：合成是 `graph.json` 里的一个**普通 node**

- 合成节点 `m*`：`deps` = 该 topic 的**全部内容节点**；`owner: "child"`（该字段当前不被消费，见前置事实④ ⇒ **本篇不依赖它**）；`deliverables: ["nodes/<m-id>/RESULT.md"]`。
- 父照常 `ready` → `claim` → `subagent` → `close` ⇒ **零新增调度逻辑**：deps 门控（`lib/plan-topics.ts:435-440`）自动保证「内容节点全 done 后合成节点才可派」；`attempts[]`/`in_flight`/`fence`/`converged` 全部自动覆盖（`:453-461` / `:678-699` / `:871-906`）。
- **合成节点的发现规则**（两套并行，缺一不可）：
  - **文档惯例**：合成节点 id 前缀 `m*`（如 `m1`）；
  - **结构特征**：其 `deps` 覆盖全部**内容节点**（内容节点 := 全部非 cancelled 且非 `m*` 的节点 —— **不依赖 `owner`**）。
  - ⇒ 惯例负责「**指认**」，结构负责「**核对**」（V5）。二者互相加固：惯例可读，结构不可漏。
- **不新增 agent、不新增派发通道**：
  - 不新增 agent 的依据：合成节点写域与 `plan-worker` **完全相同**（`*.rddf/plan-topics/*`），模型档位由 D3 解决 ⇒ 零新 prompt / 零配置 / 零守卫 / 零回滚字节钉死。
  - checker 零改动的逐项确认见方案稿 `§4.4`（`lib/plan-topics.ts` 与 `scripts/plan-topic-check.ts` **一行未改**）。
- **口径边界（与 D5 配套）**：**既有机制面判据零改动**（`plan-topic-check` 的 20 码闭集与四值退出码不变、`lib/plan-topics.ts` 与 `scripts/plan-topic-check.ts` 一行不动）；**质量判据 V4/V5 另立载体**（B1 新增，见 D5）⇒ 「零改动」指**不动既有**，**不是**「无任何新增判据」。

### D2 合成产物落在**合成节点自己的 `RESULT.md`**（不另设文件）

- 父的写面**不变**（单一写者表无需新增一行）⇒ 父仍只写 `TOPIC.md` / `graph.json` / `nodes/<id>/BRIEF.md`。
- 合成稿**留在 topic 树内** ⇒ 仍**不进** `PLAN_REF_ROOTS` ⇒ 「**讨论稿 ≠ 可执行计划**」的性质保持（前置事实③）。
- ⇒ **`ADR-plan-multi-session-collaboration` 残留 #19（父的合成产物在 topic 树内无位置）由本篇闭合**：位置 = 合成节点自己的 `RESULT.md`。
- 父**可以**读该文件作为 topic 级答案（成本 = 合成稿体积，**不是**全部子产出体积）。
- **作者 ≠ 背书（本篇明写，闭合责任归属缺口）**：
  - **作者 = 合成节点**（子会话）—— 留痕、可 A/B、可重建；
  - **背书 = 父的采纳判断** —— **不可机判**（与 D11「`converged` 是调度信号、非交付信号」一脉相承）⇒ topic 的答案**成立与否由父负责**，不由 `converged=true` 背书。
- **父不修订合成稿**：修订 ⇒ 父成为该文件的第二个写者 ⇒ 破单一写者。
  ⇒ **合成质量不达标时的路径是「追加式」**：**新增**合成节点 `m2`（`deps` 同为全部内容节点、BRIEF 指摘 `m1` 的缺陷），`m1` **保留为审计痕迹**；**惯例取「最新一个非 cancelled 的合成节点」为答案**。
  ⚠ 「取消 `m1` 后重开」**不是**可用路径：合成质量不达标的典型场景恰是 `m1` 已 `done`（产物在盘），而父篇 D9 **禁止「完成后取消」**（由 `cancel` CLI 硬拒）⇒ 死路。**仅当**合成节点**尚未 done** 时方可 `cancel` 后重建。

### D3 模型策略：三档阶梯，默认 **A 档**

| 档 | 做法 | 成本 | 状态 |
|---|---|---|---|
| **C** | 现有 `plan-worker`（弱模型 `opencode-go/deepseek-v4.1-flash`）做合成 | 零 | ⚠️ **已实测，部分达标**（见 D4） |
| **A** | `subagent(agent="plan-worker", model="<强模型>")` —— 每次派发覆盖模型 | 零 paperwork | **采纳** |
| **B** | 新增 `plan-merger` agent（模型写在 agent 配置里） | 一条 ADR + 双审 + 新 prompt + 守卫 + 文档投影 + 回滚字节钉死 | 兜底（A 档失败才启用） |

- **C 档实测结果**（A/B 对照，vs 父手写 golden standard）：结论一致性 **5/5**（且修正 golden 的 3 处措辞、新增 1 条 golden 没有的过期快照）；裁决项覆盖 **31/31**（优于 golden 的 17 合并口径）；缺陷清单覆盖 **17/18**，但**丢掉了上游明确标为「最重」的一条** ⇒ **S1 判 FAIL** ⇒ 升 A 档。
- **A 档的纪律裁决（用户已裁）**：`subagent` 的 `model` 入参说明写着「NEVER set this unless the user explicitly asks for a particular model or variant」。⇒ 本篇裁定：**机制性覆盖算「用户明确要求」** —— 理由：本机制会写进 `prompts/plan.md`，父是**被指示**设置；该说明的立法意图是防「随手乱设模型」，不是禁「按机制设定」。⇒ 代价：`prompts/plan.md` 必须**显式写明该覆盖是机制的一部分**。
- ⚠ **上游语义依赖（两级）**：A 档依赖「`subagent` 每次派发可覆盖模型」（前置事实①）。
  - **源码层**：可锚定 ⇒ 采纳即必须在 `scripts/check-upstream-anchors.sh` 补一条**语义 token 锚点**（照 P1–P6 / P5b 体例：**只写语义、不写行号、不钉函数名**）；且**任何文档引用都不得把行号当契约**（同一语义在本仓 canonical 源码根是 `:171`、在 `v2.2.5` tag 上是 `:190` ⇒ 漂移 19 行 ⇒ **P5 锚点假红事故的同型**）。
  - **provider 层**：⚠ **锚点钉不住** —— 锚点只能钉上游源码里「模型覆盖优先级」这条语义，**钉不住 provider 是否真换模型**（模型白名单校验拒识 ⇒ spawn 失败）。⇒ 后果落到父篇残留 #18 的 `claim`→`spawn` 无补偿缺口上（**悬挂 attempt ⇒ 需人工 `reap --confirm`**）⇒ 本篇**不新增**机制，只**登记**（见「已知不可机判清单」）。
  - ⇒ **落地次序**：P7 锚点**批内先于** `prompts/plan.md` 的写入点执行（假红即停，勿写 prompt）。

### D4 BRIEF 契约新增一条**结论层硬判据**

合成节点的 BRIEF 必须显式要求：

> **凡被上游节点标为「最重 / 必须上报 / 薄弱点 / 缺陷」的发现，必须进结论层（反哺清单），不得只作依据引用。**

- **依据**：C 档实测的**唯一实质失效** —— `nodes/n3/RESULT.md:302` 原文「**薄弱点 1（最重）：`git merge` 绕开 commit-gate**」在合成稿的 §4 反哺清单中**匹配数 = 0**（`commit-gate` 全文只出现 2 次且都在裁决表里）⇒ **信息进了文档但没进结论层**。
- ⭐ **可实现性前提（本篇新增，缺任一则 V4 退化为语义匹配、不可机判）**：
  1. **稳定 token**：上游节点 RESULT 里的「最重/必须上报」标注必须携带**稳定标识**（`path:line` 或约定 slug）⇒ 否则「同一发现」的跨文档对应只能靠语义匹配；
  2. **结论层可定位**：合成 BRIEF 的**五节固定结构**（§结论 / §各节点结论的合并 / §父的裁决汇总 / §反哺清单 / §不声称的东西）使「结论层」成为**结构上机器可定位**的位置（§反哺清单即结论层）⇒ BRIEF 模板与判据**共用**这两条约定 ⇒ **必须先设计再落地**（D6 B1 步骤 0）。
- **通用性**：该判据适用于**所有**合成类 BRIEF，不限于本方案。
- ✅ **实测支撑（2026-11-26 A 档）**：带 `path:line` 的三条已知缺陷 **3/3 进入 §4 反哺清单**（C 档对照为 **0/3**）⇒ 「稳定 token」这条约定**有效** ⇒ D4 的判据方向与可实现性前提均被实测支撑。
- ⚠ **覆盖边界（不可夸大）**：V4 只能验证「**被标了**的项进了结论层」，**不能**验证「该标的都标了」（显著性标注本身是上游的**自述**）⇒ 见「已知不可机判清单」。

### D5 判据层沿用既有两维；质量判据**独立承载**

- 沿用「阶段（dispatch/final）× 严重度（阻断/info）」；`converged` 沿用 D11 口径（**调度信号，非交付信号**）。
- **不扩退出码**（四值）、**不改 `PLAN_REF_ROOTS`**。
- **20 码闭集的处理（口径修正）**：V4/V5 是**质量判据**，**不进** `plan-topic-check` 的 20 码闭集与四值退出码（否则同时破 D1 的「零改动」与 V2 的「零改动」）⇒ **B1 为 V4/V5 指定独立载体，路径在本篇钉死**：
  - **载体 = `scripts/plan-synthesis-check.ts`（自包含 CLI）+ `tests/plan-synthesis.test.ts`（其单测）**；
  - **自包含**（不 import `lib/plan-topics.ts`、不改 `lib/**`）⇒ V2 的「`lib/plan-topics.ts` 零改动」**严格成立**；
  - ⚠ **须做一次显式的新增文件闸门决定**：`scripts/`、`tests/` 新文件**不在任何既有清单内**（本仓现状，`ADR-plan-multi-session-collaboration` 对同类的处理是先例）⇒ 新增这两个文件须**显式登记**并过一次决定，不默认继承。
  - ⇒ 载体路径**必须在本篇钉死**的原因：回滚登记表的 `declared` 态要求 `watch[]` 列出**未来路径**且**这些路径当前不得存在**（`lib/rollback-registry.ts` 的 M4）⇒ 载体路径若不钉死，登记表无法合法登记本机制。

## 选项对比表

| 方案 | 结论 | 理由 |
|---|---|---|
| **合成作为 DAG 里的普通 node（D1+D2）** | **采纳** | 所需机制（deps 门控 / claim / close / fence / converged / scope-check / deliverableOk）**全部现成** ⇒ 机制面 checker 零改动；父的写面不变 ⇒ 治理面零改动；合成稿留树内 ⇒ 「讨论稿 ≠ 可执行计划」保持 |
| **合成作为新增 agent（`plan-merger`）** | **否决**（降级为 B 档兜底） | 需要一份与 `plan-worker` **写域完全相同**的 agent ⇒ 只为换模型档位 ⇒ 却要付新 prompt / 守卫 / 文档投影 / 回滚字节钉死的全部成本 ⇒ 违反「最小改动」 |
| **合成由 `plan` 主会话自己做（现状）** | **否决** | 根吸收全部子产出（实测 244,703 B / +114,842 tokens）；合成质量**无痕**、换根不可重建；与「派生而非自述」范式冲突（合成稿是自述产物） |
| **合成作为 `delegate` 通道的一环** | **否决** | delegate 是工程实施派发（写隔离 / 单槽 / `scope` 差集 / 停机证据）；合成是**只读汇总** ⇒ 用 delegate 会把「不需要写权限的动作」塞进「为写权限设计的通道」，并白付一次派发与占槽 |
| **合成产物放 `.rddf/plans/<slug>.md`** | **否决** | 该根**在** `PLAN_REF_ROOTS` 内 ⇒ 合成稿会从「离线讨论产物」变成「正式件」（可被派工程）⇒ 破坏「讨论稿 ≠ 可执行计划」；且需新增父的写面（改单一写者表） |
| **新增 `SYNTHESIS.md`（父写合成产物）** | **否决** | 与 D2 重复（合成节点自己的 RESULT 已够）；若父要**修订**它 ⇒ 双写者（父 + 子）⇒ 破单一写者；若父只搬运 ⇒ 多一份可漂移的副本 |
| **父只读各节点 RESULT 的「结论」节、不读全文** | **否决** | 可再砍材料吸收，但**合成本质要求通读全文做取舍**（C 档实测的 31/31 裁决覆盖正是通读的产物）⇒ 选择性阅读换的是**质量**，不是免费午餐 |

## 后果 / 代价

**正面**
- 根的**材料吸收量**从 244,703 B 降到 **35,265 B（-86%）**（按 D2 的答案惯例取**当前答案节点** = 最新非 cancelled 合成节点 = A 档的 `m2`）；C 档 `m1` 的对应数字是 27,112 B（-89%）。合成工作整体移入一个**隔离会话**（实测最终上下文 **132,909 tokens**）⇒ 根会话保持清醒。
- 合成**从自述变成留痕产物** ⇒ 换根会话可重建「父当时合了什么」。
- 合成质量**可判定**（A/B 对照 + V4 的机械判据）⇒ 「合并得好不好」不再靠散文。
- **零机制面改动** ⇒ `lib/` 与 `scripts/plan-topic-check.ts` 不动；治理面改动仅限 `prompts/plan.md` 一节 + 一条锚点；**回滚面 = 回滚登记表的 `plan-synthesis-offload` 条目**（`state: declared`，**B0 已增** —— 新建 ADR 触发登记表 M1「ADR 未被覆盖 = 沉默即违规」）；**机制面零改动 ⇒ 无字节钉死清单**；B1 落地后须写 `.rddf/rollback/plan-synthesis-offload.json` 清单并转 `proving` ⇒ drill PASS 后转 `active`（见 D6 B1）。

**负面 / 代价**
- **断裂点不变**：合成会话自身仍要装下全部子产出 ⇒ 「单个合成装不下超大 topic」**未解决**（**不可缓解**）⇒ 本机制**不得**被宣传为「让规模无上限」。
- **新增一条上游语义依赖**（D3，源码层可锚、provider 层不可锚）⇒ provider 层不兑现时**静默**降级，且落到残留 #18 的悬挂 attempt 缺口上。
- **D4 的结论层纪律若只写在 prompt 里则无效** ⇒ 必须配机械判据（V4）⇒ 实现批要先做一次判据设计（不是零成本）。
- **「deps = 全部内容节点」是登记约定** ⇒ 父若漏把某节点并入合成节点的 deps ⇒ 合成**静默漏项**（无任何信号）⇒ V5 是唯一防线，而 V5 依赖「内容节点集合」的口径 ⇒ 口径必须 owner-free（已如此，见 D1）。
- **合成稿与节点产物压在同一文件** ⇒ 父不修订它 ⇒ 返工走**追加式**（`m2`），代价是同一 topic 存在多份合成稿 ⇒ 需「取最新非 cancelled 合成节点为答案」的惯例（已写进 D2）。
- A 档的模型覆盖与 `subagent` 工具说明存在**字面张力**（D3 已裁定）；若上游收紧该参数语义 ⇒ 合成质量回落且**无告警**。

**风险**
- 上游语义漂移：锚点只能覆盖源码层；provider 层不兑现 ⇒ 无源码信号 ⇒ 合成质量静默下降 ⇒ 与 2026-11-25 的锚点假红事故同型（漂移的代价不是「判错」而是「闸门本身坏掉」）。
- 「最重项降级」类失效在 A 档下**未必自动消失** ⇒ V4 的机械判据是主要防线，不是模型强度。
- ⭐ **「合成稿已过时」有机械信号（白送，父篇 D10 的性质）**：父给合成节点**补** dep ⇒ 该节点已闭合的 attempt 触发 `stale_inputs`（`lib/plan-topics.ts:678-699` 的 fence 自动覆盖）⇒ 「漏登记」在**父改图之后**仍会被逮住；**只有「父从不改图」才逮不住**（那正是 V5 的存在理由）。

## 已知不可机判清单（如实登记）

| 项 | 为何不可判 | 现行兜底 |
|---|---|---|
| 合成稿**语义**是否正确（合并有没有曲解各节点） | 无判据可表达「这份合并忠于原文」 | A/B 对照（V8）+ 父抽检 diff + 合成稿每条结论必须可回指到子节点小节 |
| 「最重项」的**充分性** | 上游的显著性标注是**自述**（子自己说「这条最重」）⇒ 判据只能验证「被标了的进了结论层」，**不能**验证「该标的都标了」 | 上游节点的「薄弱点/必须上报」写法约定 + 父复核 |
| 合成节点是否**漏了**某个内容节点 | 「deps = 全部内容节点」是父的登记约定；无独立真值可对照 | **V5a（并集口径）** + 父事后补 dep 时已闭合 attempt 触发 `stale_inputs`（D10 白送）⇒ 只有「父从不改图」才逮不住 |
| 父**修订**合成稿后的正确性 | 父修订会破单一写者（见「后果/代价」） | 本篇**不支持**父修订 ⇒ 走**追加式**（新增 `m2`，`m1` 保留为审计痕迹；惯例取最新非 cancelled 合成节点为答案）；**仅当**合成节点尚未 done 时方可 `cancel` 后重建 |
| 合成会话能否装下超大 topic | 内容体量决定 | **不可缓解** ⇒ 断裂点须在机制文档明写 |
| **对「可变文件」做 `path:line` 引用会随内容漂移** | `graph.json` 等文件在 topic 演进中**行号会移**（A 档实测：加一个合成节点后，`n5` 的活体实例从 `:141`/`:146` 漂到 `:142`/`:147`，**+1**）⇒ 行号不是稳定标识 | 引用**可变文件**须给**内容锚**（如「`graph.json` 中 `owner: "parent"` 那一行」）而非行号；与 D3 的「行号不是契约」同型，但**对象不同**（D3 说的是上游源码，本条说的是**本仓内会演进的文件**） |

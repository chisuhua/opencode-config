## 3. oracle 审查（治理面档，第一审查者）

判定：**`治理面判定: PASS-WITH-NOTES`**（0 BLOCKER / 1 高 / 1 中 / 2 低）

| # | 严重度 | finding | 处置 |
|---|---|---|---|
| O1 | 高 | **未覆盖清单第 2 条事实不准确** —— 原写「少写一项不会被抓到」，实际「删到只剩 1 项」会被 `terms.length < 2` 抓到；真正的漏洞是「**换项不删项**」 | **已修**：清单改写为「换项不删项抓不到；删到只剩 1 项会被项数 < 2 抓到（那是**删项**面）」 |
| O2 | 中 | 未覆盖清单**漏登两条假绿面** —— ① 「意图未定」是**全文 token** 检查 ② 组成词 / 真源指针只要求出现在文件任意位置 | **已修**：两条补进清单 |
| O3 | 低 | expect 关键词的**唯一性**是隐式不变式 ⇒ 建议加显式红灯 | **已采纳**：违规条目加 `cls` + 突变断言要求「关键词命中的消息全部属于期望判据类」+ 新增「判据类 ↔ 关键词」用例 |
| O4 | 低 | oracle 因 shell 只读白名单**无法执行测试** ⇒ 需调用方实跑 | **已做**：`bun test tests/config-guards.test.ts` → 106 pass / 0 fail；`bun test tests/` → 591 pass / 0 fail |
| O5 | 不采纳 | 建议把「处置口径」判据从 token 级升到句子级 | **不采纳**（同 oracle 自己的判断）：措辞自由度骤降、误伤面上升，超出「只钉文本形态」的口径；已登记为「判据收紧 = 独立批次」 |

## 4. critic 审查（`build` 档；operational 判据 = 治理面行 + 降级自检清单 6 条）

判定：**`APPROVE`**｜`mergeable: yes`｜`scope_exceeded: false`｜**0 BLOCKER / 0 SHOULD_FIX / 3 NIT**

critic 核过：与既有 10 个守卫族**无重复、无矛盾**（「subagent 输入契约」族不钉意图词表；「审查链与预算」族只比数字集合、不钉预算格内容；「被派发后端降级例外」族钉的是别的段的 `HANDOFF: blocked`）；「判据类 ↔ 关键词唯一」是**测试内部的元不变式**，与规则层的「判定词表单一真源」不同层 ⇒ 不构成第二套判定标准；降级自检 6 条逐条通过。

| # | 严重度 | finding | 处置 |
|---|---|---|---|
| C1 | NIT | 「至多 1 轮」判据针**只有一条突变**（删「不另计」）⇒ 该针的判别力未实测 | **已修**：补一条突变「删掉『至多 1 轮』」（⇒ 17 类突变） |

### critic 的验证建议 → 已做：唯一性用例的**反向抽查**

critic 指出该用例的判别力当时只有「实现过程中抓到过一次碰撞」这条非可复跑证据 ⇒ 补了**可复跑的反向抽查**：

```
注入：把「删掉检查点小节标题」那条突变的关键词从完整标题改回「意图检查点」（= 跨两个判据类的那一个）
结果：判据类 ↔ 关键词 用例**变红** —— 「关键词「意图检查点」出现在多个判据类的消息里（调用方侧 / 投影同步）」
恢复：改回完整标题 ⇒ 106 pass / 0 fail
```

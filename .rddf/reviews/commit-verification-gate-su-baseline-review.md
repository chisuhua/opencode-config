## 3. oracle 轮（治理面）逐条应答

| # | finding（摘要） | 处置 |
|---|---|---|
| S1 | **误命中方向未登记、无特异性约束** ⇒ 宽 `match`（`"3 fail"` ⊆ `"13 fail"`）会放过真回归；且巡检层若复用子串语义，对「失败数膨胀」同样不敏感；「不发明第二套语义」的声称**失实**（子串弱于失败标识集合） | ✅ 采纳：**D10①** 增「特异性约束」（`match` ≥ 8 字、非纯数字/通用词，守卫断言）+ **D10②** 改为如实口径（commit 路径 = 子串，**弱于** `KNOWN_FAILURES.txt` 的集合比对；巡检层按**失败标识/计数**算集合比对，**不复用子串**）；**后果段**补「风险 ②（误命中方向 · 更危险）」并给出 `3 fail` / `13 fail` 的具体例子与缓解 |
| S2 | 「巡检层各仓自选」与「新增失败必须红」**自相矛盾** ⇒ 若自选 = 可选 ⇒ 单调性无人执行 ⇒ 真回归静默放过（本 ADR 已有同型史实：插件静默消失两天、206 单测全绿） | ✅ 采纳：**D10②** 改「**载体自选，但必须存在巡检载体**」（守卫断言其存在，形态同 D9①「声明须 git-tracked + 守卫钉住」）+ **巡检缺席 ⇒ `known_failures` 字段整体无效 ⇒ 退回 D2① 硬门**（并写明「失效的是该字段，不是整个声明作废 ⇒ 放行」，避免与 D3 叠成 fail-open）；**后果段**补「风险 ③（机制在、没人跑）」 |
| S3 | 新增放行面**未登记 D9⑰** ⇒ 不靠审查就会漏 | ✅ 采纳（**处置方式经分歧点名后调整**）：新增 **D10③′「本面登记（免宣称面）」**（防什么 / 不防什么 / 缓解三列），并把「实现另案落地时登记为 **D9⑰**（四面同批）」写成 **V25** 的**强制义务**（未登记 ⇒ 红）。⚠ **本 SU 不提前改 D9 表**：守卫硬断言「恰 16 项」且要求四面覆盖，而 **AC 面载体**属实现另案（架构师不创建 openspec change）⇒ 提前改表会立刻打红治理仓测试。**该处置的判定依据见 critic 轮**（focus 2） |
| S4 | **运行时零留痕** ⇒ 与「审计链完整」的声称有落差（无法区分「真绿」与「baseline 命中」） | ✅ 采纳：**D10①** 增「运行时留痕」（命中放行时输出一行**非抛错**提示 `baseline 命中: <command> / match=<…>`）；**V20** 增对应断言（命中但不留痕 ⇒ V20 红） |
| S5 | 实现歧义未定：同一 command 多条目 / `match` 作用于 stdout 还是 stderr | ✅ 采纳：**D10①** 钉死「同一 command **允许多条目**，任一命中即放行」+「`match` 作用于 **stdout + stderr 合并输出**」 |
| S6 | 「5 → 12 个文件/天」把单间隔两点外推成速率；`format.sh --check` 不接受文件列表系 CppTLM 仓事实、本次未独立复核 | ✅ 采纳：**D10④** 改为「一天内 5 → 12（**单点观察，非稳定速率**）」；占位符否决的**第一理由**改为「**变更集绿 ≠ 主干绿**」（独立成立），CppTLM 事实降为第三条并标注未独立复核 |

## 4. critic 轮（arch 档）逐条应答

**判定**：**REJECT**（`mergeable: no` / `scope_exceeded: false`）—— 2 BLOCKER + 4 SHOULD_FIX + 1 NIT。

| # | finding（摘要） | 处置 |
|---|---|---|
| C1 | **「巡检缺席 ⇒ 字段无效」的 fail-closed 没有 commit 路径的执行者**：巡检存在性守卫若作为普通测试住在 `verify_commands` 里，其失败输出会被**同命令**里已 baseline 命中的条目**一并吞掉**（D10① 判定粒度 = 命令 + 合并输出子串）；且「谁在何时判定缺席」未指明 ⇒ 两种读法安全方向相反 | ✅ 采纳：**D10②** 增「**该 fail-closed 必须在 commit 路径上有执行者**」+ 三条硬约束：① 巡检存在性守卫必须是 `verify_commands` 的**独立条目**（不得与其它命令共享合并输出）；② **任何 `known_failures` 条目不得绑定该巡检守卫命令**（绑定即条目无效、不放行）；③ **巡检载体文件必须 git-tracked**；并钉死「缺席判定发生在 **commit 时**（存在性 + 绑定检查），**CI 事后发现不能替代它**（事后 ⇒ 已放行 ⇒ 无效）」。**V25①** 增变红判据「baseline 绑定巡检守卫 command ⇒ 红」 |
| C2 | **⊆ 交付不了「不能增」**：同一次提交里「制造新失败 + 登记对应条目」后，新条目仍 ⊆ 实际失败集合 ⇒ 巡检绿 ⇒ baseline 实增；且「不能增」的唯一执行者（**声明内容守卫**）未被指派，V24 按 ⊆ 语义可平凡满足 | ✅ 采纳：① 「baseline 只能减不能增」从 ⊆ 断言上**摘下**（⊆ 只保证**防腐坏**）；② **D10③** 增「『不能增』由**声明内容守卫**保证（D9① 的形态扩展到 `known_failures` 字段：守卫**逐项相等**断言该清单，改清单 ⇒ 守卫红；使用方仓由巡检载体承担同职）」+ 明写 ⊆ 为何交付不了；③ **V24 拆成两条独立判据**（① 防腐坏 / ② 防增长）并各自带变红演练 |
| C3（should_fix） | D2① 判据行未挂 D10 指针 ⇒ 同一决策两处表述，违反本文「唯一定义处」纪律 | ✅ 采纳：D2① 行内联「**SU 2026-11-27 / D10**：失败**且命中** `known_failures` ⇒ 视为通过；未命中仍拒」（沿本文 Rev 2/3 的内联惯例） |
| C4（should_fix） | 元数据「修订」行的 SU 段 ~500 字复述 D10④ ⇒ 构成第二真源 | ✅ 采纳：该行压缩为指针（「决策与依据见 **D10**」），实测数字与必答题答案只留在 D10④ |
| C5（should_fix） | 未钉「另案落地时同批更新 `.rddf/rollback/commit-gate.json`」的义务 ⇒ 回滚清单漂移 + drill 兜底不再覆盖新增件 | ✅ 采纳：新增 **D10⑥**（回滚面同批义务：新增守卫 / 巡检载体 / baseline 字段相关的 delete 与 edits 条目） |
| C6（should_fix） | 示例 `"match": "3 pre-existing failures"` 自带计数前缀碰撞（正是风险②的形态），而特异性守卫拦不住 | ✅ 采纳：示例改为 `"pre-existing failures in test_llm_cache"`（无计数前缀） |
| C7（nit） | 「四面同批」与 D9 前言的「三处载体（不含本表）」口径差 ⇒ 后人可能把真源当登记面 | ✅ 采纳：两处措辞改为「**ADR 表（真源）+ 三处载体**（测试注释 / 主题文档 / AC 面载体）同批」 |

**复审提出的 2 条 SHOULD_FIX（本次一并落地，纯文本一致性修正，不新增决策）**：

| # | finding | 处置 |
|---|---|---|
| R1 | 后果段「风险 ③」的因果链仍是修复前的旧框架（「巡检缺席 ⇒ 单调性无人执行 ⇒ baseline 只增不减」），会让实现者把「防增」误划给巡检 | ✅ 已改：风险 ③ 改为「**若 fail-closed 未落实** ⇒ …」，并明写修复后口径（**「防增」归声明内容守卫**；巡检缺席时 baseline 根本不适用 ⇒ 字段无效 ⇒ 硬门） |

# BRIEF — m1：合成稿

## 目标

把本 topic（`v7-probe`）各内容节点（`deps` 所列 `n1`–`n7`）的 `RESULT.md`
**收敛**成**一份** topic 级合成稿，写入 `nodes/m1/RESULT.md`。

**「收敛」不是「拼接」**：输出应远小于输入（输入规模以磁盘实测为准）⇒ **你要做的是判断与取舍，不是搬运**。

## 边界（明确不做）

- **只读** `nodes/n1..n7/RESULT.md`（以及 `TOPIC.md`）。**不写** 任何其它 node 的目录
  —— 包括 deps 节点的 `RESULT.md`（**读可以，写不行**）。
- 不改 `graph.json` / `TOPIC.md` / 任何 `BRIEF.md`。
- **不写** `.rddf/plans/**` —— 本合成稿是**离线讨论产物**，不是正式件
  （`.rddf/plan-topics/**` 不在 `PLAN_REF_ROOTS` 内 ⇒ 天然不可派工程）。
- 不引用「上游语义（未在本仓核实）」以外的来源；找不到依据就如实标注，**不得编造 `path:line`**。

## 期望交付（`nodes/m1/RESULT.md`）

**恰好五节**，顺序固定：

### 1. 结论
- 3–5 条，每条**一句话可判定**（能判真假的布尔陈述或单句结论）。
- 每条注明它**来自哪个 node 的哪一节**（如 `n5 §0`）。

### 2. 各节点结论的合并
- 一张表：节点 → 它的结论（压成一行）→ 父的取舍（采纳 / 修正 / 否决 + 一句理由）。
- **必须覆盖 `n1`–`n7` 全部 7 个节点**，一行都不能少。

### 3. 父的裁决汇总
- 收集各节点 RESULT 里的「待父裁决」项，**逐条**给出裁决。
- 每条格式：`# | 事项 | 裁决`。
- **每条裁决都要有依据**（引用那个节点的哪一节，或哪条 `path:line`）。

### 4. 反哺清单
- 对**既有 `plan` / `plan-worker` 机制**的反哺，每条四字段：
  `现象 | 依据 path:line | 建议动作`（+ 可选分类标签）。
- 分类建议：`【声明与实现脱节】`/`【自述/命名】`/`【流程纪律】`/`【插桩位空转】`/`【模板复用风险】`/`【本次场景活体复现】`/`【顺带发现】`。
- **每条必须落到「现象 + 依据 path:line」**，不得写成泛泛建议。

### 5. 本 topic 不声称的东西（诚实口径）
- 3–6 条，每条一句话。
- 必须包含「**不可机判的是什么**」这一类。

## 验收口径

- **可回指**：第 1、3 节每条结论都能指到某个 `nodes/<id>/RESULT.md` 的**具体小节**。
- **覆盖完整**：
  - 第 2 节覆盖 `n1`–`n7` **全部 7 个**；
  - 第 3 节的裁决项**条数 ≥ 各节点「待父裁决」的总条数**（不得遗漏；可以合并同类项，但合并后仍要逐条可追）；
  - 第 4 节每条都有 `path:line`。
- **诚实口径**：凡「上游语义（未在本仓核实）」/「不可机判」/「需要人裁决」的，必须**如实标注**，不得写成已解决。
- **长度**：正文 **≥ 100 行**；末行写 `## STATUS: COMPLETE`。
- **收敛性**：输出 **≤ 40,000 bytes**（超过即说明你在拼接而非收敛）。

无（本 topic 无父裁决；全局约束见 `TOPIC.md`）。

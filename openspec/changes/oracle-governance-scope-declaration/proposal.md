# oracle-governance-scope-declaration — 删掉 oracle 的「审查域猜测」，改由调用方声明 + 可解析兜底

> 来源：`oracle-intent-gate-e2e` 的 **E-A 实测**（e2e 仓 `e93738c`；观察报告
> `rdd-workflow-e2e/.rddf/reviews/oracle-intent-gate-e2e-observation.md` 的「AC2/AC3/AC4 E-A 实测」节）
> 判据真源：本文件「## 验收标准」表（AC1a–AC6）；实施步骤与取舍见 `design.md` / `tasks.md`（builder 阶段）
> 性质：**治理面**（`prompts/oracle.md` + `prompts/build.md` + 守卫断言）⇒ 需 **oracle → critic** 各 1 轮
> ⚠ **本路径未启用 `rdd-planner` / `rdd-builder`**：canonical 前置不存在 ⇒ 走**内置流程**（用户选定 ①）
> ⚠ **自指审查**：改 `prompts/oracle.md` 的模式段 ⇒ 审查实例跑的是**旧契约** ⇒ 该轮 oracle 结论
>   **不构成独立证据**（`prompts/build.md` 的「自指审查」条）。替代取证 = 静态守卫 + e2e 观察。

## Why

### 实测到的事实（非推断）

E-A 做了一次**项目 ADR 审查**（`docs/adr/draft-002.md`，明确要求「审查模式」+ 判据）：

| 项 | 实测 |
|---|---|
| 父模型是否带意图陈述 | ✅ 带了（入参含真源派生的**全部**组成词） |
| 父模型入参里是否提到「治理面」 | ❌ **没有**（`grep 治理面` 零命中） |
| oracle 返回的判定行 | **`治理面判定: BLOCK`**（第 18 行）—— 用治理面词表审了**非治理面**对象 |
| 契约词表 `判定: APPROVE\|REJECT` | ❌ 从未出现 |

### 根因：**一条猜测分支**，不是「缺一个字段」

`prompts/oracle.md` 的「模式」段：

> 输入明示「治理面」，**或判定对象属治理面** ⇒ `治理面判定: PASS | BLOCK | PASS-WITH-NOTES`
> （治理面范围见 `prompts/build.md` 的作用域表；……）

- 前半句（「输入明示」）**本来就是声明通道** —— 只是没人用它；
- 后半句「**判定对象属治理面**」是**猜测分支**，且它指向的作用域表是**本仓路径** ⇒ 对**别处工程**
  的路径无法解析 ⇒ 模型只能按「看起来像架构决策」猜。
- ⇒ **实际修复是删掉这条猜测分支**（连同那句指针）。「新增声明语法」只是**替代通道**，不是修复本体。

### 为什么非修不可（失配方向不对称）

| 失配方向 | 后果 |
|---|---|
| 其他审查被误判成治理面 | 契约词表不出现 ⇒ **可被下游断言发现**（E-A 就是这样抓到的） |
| **治理面审查被误判成其他审查** | `BLOCK` 的语义消失 ⇒「`BLOCK` 或未应答 finding ⇒ 不得收口」**fail-open** ⇒ **静默放行** |

⇒ 后者危险。现在没发生只是因为模型**恰好**偏向治理面 —— **是运气，不是判据**。

## What Changes

### A. 审查域判据：**三层，且第三层必须有消费方**

`prompts/oracle.md` 的「模式」段把猜测分支替换为：

| 优先级 | 输入 | 判定行词表 |
|---|---|---|
| 1 | 声明 `审查域: 治理面` | `治理面判定: PASS \| BLOCK \| PASS-WITH-NOTES` |
| 2 | 声明 `审查域: 其他审查` | `判定: APPROVE \| REJECT` |
| 3 | **未声明**，但输入含 **`~/.config/opencode/` 前缀路径** | `治理面判定: …`（**可解析** ⇒ 不需要猜） |
| 4 | 未声明、且无可解析治理面路径 | `判定: …` **+ `建议` 段首行标注** `审查域=未声明（默认其他审查）` |

- **为什么第 3 层成立**：治理面路径集**恒带 `~/.config/opencode/` 前缀**（绝对路径）⇒ 在**任何工程的 cwd** 下
  都可字面匹配；真正「无法解析」的只有**别处工程的路径**（`docs/adr/**` 等）⇒ 那正是第 4 层。
  **这比「未声明一律默认」安全**：治理面审查即使漏声明，也有路径兜底。
- **术语**：用既有的「**其他审查**」（`oracle.md:51` / `SUBAGENT-ORCHESTRATION.md:98` 已在用），
  **不新造「项目域」** —— 否则 `build.md` 降级自检第 3 条（第二套判定标准）会当场命中本 change 自己。
- **声明与路径冲突** ⇒ 按**更严者**（治理面），并在 `建议` 段首行标注 `审查域=声明冲突（按治理面）`。
- **非法取值**：`审查域:` 出现但值不属 `{治理面, 其他审查}`（含大小写 / 空格 / 拼写变体）⇒ **视同未声明**
  （走第 3/4 层），并在标注里**回显原值** ⇒ 解析失败**可见**，不静默。
- **组合态（与 v2.37 的意图前提）**：**意图未定 ⇒ 不给任何判定行**（优先于本表）；
  「声明了审查域但无意图陈述」⇒ 走意图前提表的第三行（拒发），**不**走本表的未声明兜底。

### B. 标注的**消费方**（否则闸门仍然 fail-open）

`prompts/build.md` 的「治理面判定（verdict）」段新增一条硬条件：

> **治理面审查的判定行必须是 `治理面判定:`**；若见到 `审查域=未声明（默认其他审查）` 或 `判定:`
> ⇒ 该轮**审查不成立**（既非通过、也非失败）⇒ **不得收口**，补齐声明后重跑。

- 措辞与既有「已调用但拒发判定行 ⇒ 审查不成立」**并列**，**不新造第三态**；
- ⇒ 漏声明不再是「日志」，而是**闸门**。

### C. 调用方义务（含被派发后端，口径一致）

- `prompts/build.md` 的 **治理面行**：调 oracle 做治理面审查**必须**在输入里声明 `审查域: 治理面`；
- **被派发后端**：缺声明 ⇒ **不 block** —— 走第 3/4 层兜底 + 在响应里报告「声明缺失」。
  **理由**：v2.37 的「缺意图 ⇒ `HANDOFF: blocked`」是因为**意图决定审查能不能做**；审查域**只决定用哪套
  词表** ⇒ 为它作废一次派发不成比例。**两处口径差异要写进文档**（否则是双标）。
- **谁不需要声明**：`front`（理解性调用，只读）与 `plan`（架构建议 / 计划前调研）的 oracle 调用
  **从不审治理面对象** —— 它们要么在**咨询模式**（无判定行），要么是其他审查 ⇒ **第 4 层即正确结果**。
  只有 **build / architect 编辑治理面文件时** 才需声明。⇒ 声明义务的范围是**窄的、可判定的**（谁在动
  `~/.config/opencode/**` 谁声明）。

### D. 静态守卫（层 1）

`tests/config-guards.test.ts` 的「oracle 意图闸门」族扩判据：
- **行级锚定**（不整文件 `includes`）：检查映射表的**每一行右列**、verdict 段的治理面硬条件；
- **突变测试**：删第 1/3/4 层任一行、删 verdict 段的硬条件 ⇒ 必须红；
- ⚠ **同 patch 必撞的连锁**：既有断言 `config-guards.test.ts:1125-1137` 要求 `oracle.md` 含**未转义**字面
  `治理面判定: PASS | BLOCK | PASS-WITH-NOTES`。本 change 引入**表格**后单元格内 `|` 需转义成 `\|`
  ⇒ **该断言当场红** ⇒ 必须同 patch 修正它，并保证修正后仍钉住「词表只在 oracle.md 定义」。
  改守卫断言本身属治理面 ⇒ 由本 change 的 oracle→critic 轮次覆盖。

### E. e2e 闭环（层 2，**观察项 + skip 纪律**）

`oracle-intent-gate-e2e` 的 E-A：fixture 的审查请求**加声明** `审查域: 其他审查` ⇒ 期望 `判定: …`。

- **两态**：① 加声明 / ② 删声明行（harness 删）⇒ 记录**词表是否改变**（单臂 N=1 无法归因 —— 上游 E-B
  刚因同型问题降级过）；
- **skip 纪律**：`provider.rate-limit` / `status != completed` / 无 `agent=oracle` 调用 ⇒ **skip 未判定**；
- **前置**：`$SC_SRC` 的 HEAD 必须记录（跑的是**安装态**；HEAD 不对 ⇒ 观测的不是新文本）。

## ⚠ 已知边界

| # | 边界 | 处置 |
|---|---|---|
| 1 | 声明仍是**调用方义务**，可能漏 | 第 3 层**路径兜底** + 第 4 层**标注** + B 节的**消费方** ⇒ 漏声明**不能静默** |
| 2 | **声明错误**比未声明更隐蔽（声明「其他审查」却审治理面对象） | 冲突裁决 = **按更严者**（治理面）+ 可见标注 |
| 3 | 与 v2.37「意图前提」是**两条正交的输入形态要求** | 优先级写死：**意图未定 ⇒ 不给任何判定行**（优先于审查域表） |
| 4 | 本 change 的审查轮次是**自指审查** | 结论不构成独立证据；替代取证 = 静态守卫 + e2e 观察（写在文首） |
| 5 | 同一 patch 同时改两域对象（本仓常见） | 单字段无法表达 ⇒ 规则：**按治理面声明**（更严者），或拆两次调用 |
| 6 | 与其他 change 的 `build.md` 行序耦合 | 守卫锚点对行序敏感 ⇒ 「依赖 / 后续」登记执行顺序，避免 anchor 漂移 |

## 不做什么（scope 边界）

| 项 | 理由 |
|---|---|
| 改判定**词表**本身 | 词表是单一真源，本 change 只决定**何时用哪一套** |
| 让 oracle「更聪明地判断」审查域 | 那正是失败根因；**判据必须可操作** |
| 「未声明 ⇒ 拒发」 | blast radius 过大（所有现存调用都会变成未判定）⇒ 用第 3/4 层替代 |
| **把 oracle 纳入 `subagent-contract` 契约**（`intent` / `审查域` 结构化必填） | 这是上游已判定的**最强修法**（`lib/subagent-contract-core.ts` 的 `CONTRACTS`），但它**改变 oracle 调用形态** + 需先落地 `subagent-contract-critic-enforce` ⇒ 另立 change |
| 改 `oracle-intent-gate-e2e` 的 AC 判据 | 该 change 的 AC2 **不改**；本 change 让它在真实行为上回绿 |
| 覆盖该 change 的 `AC7-②`（需 hermetic HOME） | 独立 follow-up |

## 验收标准

| AC | 判据 | 类型 | 证据载体 |
|---|---|---|---|
| **AC1a** | `prompts/oracle.md`「模式」段含**四层映射表**（声明治理面 / 声明其他审查 / 未声明+`~/.config/opencode/` 前缀 ⇒ 治理面 / 未声明且无前缀 ⇒ `判定:` + 标注）；**`grep -c '判定对象属治理面' prompts/oracle.md == 0`**（猜测分支已删除） | 结构 | 本仓 |
| **AC1b** | `prompts/build.md` 的 **verdict 段**含治理面硬条件：见到 `审查域=未声明（默认其他审查）` 或 `判定:` ⇒ 治理面审查**不成立、不得收口** | 结构 | 本仓 |
| **AC2** | `prompts/build.md` 的**治理面行**要求调用方声明 `审查域: 治理面`；**被派发后端**缺声明 ⇒ 走兜底 + 响应报告缺失（**不 block**，并写明与 v2.37 意图条的口径差异）；并写明 **front / plan 不需声明**（咨询模式 / 其他审查 ⇒ 第 4 层即正确） | 结构 | 本仓 |

# design — oracle-governance-scope-declaration

> 判据真源：`proposal.md` 的「## 验收标准」（AC1a–AC6）。本文只记**取舍**与**实施形态**，不重复 AC 正文。
> 性质：治理面（`prompts/oracle.md` / `prompts/build.md` / `opencode.jsonc` / `tests/config-guards.test.ts`）
> ⇒ 实施完成后走 **oracle → critic** 各 1 轮；**自指审查**（改 `oracle.md` 模式段时审查实例跑旧契约）
> ⇒ 该轮结论不构成独立证据，替代取证 = 静态守卫 + e2e 观察。

## D1 修复本体 = 删猜测分支，不是加字段

`prompts/oracle.md:48` 的两条析取项里，**「输入明示『治理面』」本来就是声明通道**（只是没人用）；
出问题的是第二条「**或判定对象属治理面**」+ 它指向的作用域表（本仓路径，对别处工程无法解析）。

- **决策**：删除第二条析取项**及其指针行**；声明通道作为第 1 层，并新增第 3 层（可解析路径兜底）。
- **被否方案**：「新增 `审查域:` 字段但保留猜测分支」—— 保留即意味着模型仍可猜，E-A 的失败模式原样复现。
- **代价**：输入不含绝对前缀且未声明的治理面审查会落到第 4 层（其他审查 + 标注）。这由**第 3 层 + 收口语义**兜住（见 D3 / D4）。

## D2 四层优先级表（执行体侧）

写在 `oracle.md` 的「判定行」小节，优先级自上而下：

| 层 | 输入 | 词表 |
|---|---|---|
| 1 | 声明 `审查域: 治理面` | 治理面 |
| 2 | 声明 `审查域: 其他审查` | 其他审查 |
| 3 | 未声明 + 输入含 `~/.config/opencode/` 前缀**且按 `build.md` 作用域表属治理面**的路径 | 治理面 |
| 4 | 未声明 + 其余（含裸相对路径、`~/.config/opencode/docs/adr/**`） | 其他审查（**必须标注**） |

- **为什么第 3 层只认绝对前缀**：大仓里裸相对路径（`prompts/build.md`）无法区分「本仓治理面」与
  「某项目的同名目录」。绝对前缀是**唯一可解析**的判据。⇒ 推论：**编辑治理面时必须显式声明**（第 1 层），
  不要指望第 3 层 —— 这条写进文档，否则用户会以为「带路径就够了」。
- **前缀不是充分条件**（critic 第 1 轮 SHOULD_FIX）：`~/.config/opencode/docs/adr/**` 带前缀，但按
  `build.md` 的**本仓特例裁定**属 ADR 行（不属治理面）⇒ 未声明时**落第 4 层**。第 3 层因此写成
  「前缀 **∧** 按作用域表属治理面」，而不是「前缀即治理面」—— 否则同一对象会得到两个相反分类。
  守卫据此把第 3 层的判别词从「前缀」改成「作用域表」（前缀单独命中不再算通过）。
- **被否方案 A：未声明一律治理面** —— 会把项目审查推去治理面词表（E-A 的现状），下游契约断言红。
- **被否方案 B：未声明 ⇒ 拒发判定行** —— 所有现存调用（都还没声明）一次性变成「审查不成立」，blast radius 过大；
  且与 v2.37 的「拒发」语义混为一谈（那是意图未定，判据不成立）。
- **被否方案 C：只留声明、无兜底** —— 漏声明 ⇒ 直接落第 4 层，治理面审查静默降级。

## D3 标注必须有消费方（否则闸门仍 fail-open）

第 4 层的标注 `审查域=未声明（默认其他审查）` 若只是日志，治理面被误判成其他审查时 `BLOCK` 语义消失 ⇒
「`BLOCK` 或未应答 finding ⇒ 不得收口」**静默放行**。

- **决策**：`build.md` 的 verdict 段新增硬条件 —— 治理面审查的判定行必须是 `治理面判定:`；见到 `判定:` 或
  第 4 层标注 ⇒ **审查不成立**（既非通过、也非失败）⇒ **不得收口**，补齐声明后重跑。
- **措辞对齐**：并入既有的「审查不成立」语义，**不新造第三态**。
- **被否方案**：「标注后继续收口，只在报告里记一笔」—— 等于承认闸门可以 fail-open。

## D4 冲突裁决 = 按更严者

声明 `审查域: 其他审查` 但输入里有 `~/.config/opencode/` 前缀路径 ⇒ 按**治理面**（更严者），
并在标注里写 `审查域=声明冲突（按治理面）`。

- 理由：漏判治理面的代价（静默放行）远大于多判（只是词表更严，下游仍能读）。
- **不 block**：冲突已按治理面处理，判定行本身有效；标注只用于让调用方发现「自己声明错了」。

## D5 非法取值 ⇒ 视同未声明（解析失败可见）

`审查域:` 出现但值不属 `{治理面, 其他审查}`（大小写 / 空格 / 拼写变体）⇒ 视同未声明（第 3/4 层），
并在标注里**回显原值**。

- 理由：静默丢弃一个写错的声明，与「没声明」不可区分；回显让错误可诊断。
- **被否方案**：值不合法 ⇒ 直接拒发 —— 又回到 blast radius 问题。

## D6 与 v2.37 意图前提的优先级

两者**正交**（意图管「能不能判」，审查域管「用哪套词表」），但存在组合态：

| 组合 | 处置 |
|---|---|
| 意图未定 + 审查域已声明 | **不给任何判定行**（意图前提优先） |
| 意图已定 + 审查域未声明 | 走四层表的第 3/4 层（**不拒发**） |

- 写进 `oracle.md`：`意图未定 ⇒ 不给任何判定行（优先于本表）` —— 否则「审查不成立」有两个互相矛盾的出口。

## D7 结构上规避表格转义（不动既有断言）

proposal 的 AC4 预期「改成表格后 `|` 需转义 ⇒ 既有断言 `config-guards.test.ts:1127/1132` 当场红，须同 patch 修正」。
**实施时改为结构规避**：

- 词表的**字面定义**放在映射表**之外**的独立定义行（`治理面 = `治理面判定: PASS | BLOCK | PASS-WITH-NOTES`；…`）；
- 映射表的右列只写**词表名**（治理面 / 其他审查），不含 `|`。

⇒ 后果：
1. 既有断言**保持原样即绿**，且它仍然钉住「未转义字面只在 `oracle.md`」；
2. 若将来有人把词表挪进表格（被迫转义）⇒ 该既有断言**当场红** ⇒ 迁移被拦。

⇒ AC4 的「同 patch 修正转义连锁」子条件**不成立**（不发生冲突）。这是比原计划更省的路径，需在审稿时显式说明。

## D8 静态守卫形态：兄弟 describe 块 + 行级锚定

- **决策**：新增 `describe("oracle 审查域声明（v2.40）")`，**不塞进** v2.37 族。
  - 理由：① 两族的「判据类 ↔ 关键词唯一性」用例互相独立，混族会让关键词（如「判定行」）跨类污染；
    ② 两族判据独立演进；③ 语义上「族 = 机制」，不是「文件里的一个块」。
  - 在 v2.37 族的**未覆盖清单**里加一行指向兄弟块（保持「未覆盖清单是最新的」）。
- **行级锚定**（不整文件 `includes`）：
  - 第 1 层：行含 `| 1 |` ∧ `审查域: 治理面`；
  - 第 2 层：行含 `| 2 |` ∧ `审查域: 其他审查`；
  - 第 3 层：行含 `| 3 |` ∧ `~/.config/opencode/`；
  - 第 4 层：行含 `| 4 |` ∧ `未声明`；
  - 标注串 `审查域=未声明（默认其他审查）`（全文唯一真源，引用它而不手抄）；
  - verdict 段（切到 `**自指审查**`）：含「治理面审查的判定行必须是」∧「不得收口」；
  - 治理面行（`| `architect`（**治理面**）`）：含 `审查域: 治理面`；
  - 检查点小节：含「被派发后端」∧「不 block」∧「`front` / `plan`」；
  - 猜测分支已删：`!oracleMd.includes("判定对象属治理面")`；
  - description：含 `审查域` ∧ `prompts/oracle.md`。
- **突变测试**（共 17 条，每条必须红，且关键词唯一对应判据类）：
  1. 删第 1 层行 → `第 1 层`；

  4. 删第 4 层行 → `四层表缺第 4 层`（**不用** `第 4 层` —— 标注串 / 收口侧的消息也含该词 ⇒ 不可区分）；
  5. 把猜测分支加回 → `猜测分支`；
  6. 删标注串 → `标注串`；
  7. 删「优先于本表」→ `优先于本表`；

  12. **把新硬条件的后果从句弱化成「记录后放行」** → `新硬条件缺后果从句`
      （oracle 审出的盲区：v2.37 族的「不得收口」token 检查会被旧 bullet 满足 ⇒ 抓不到；

## D10 e2e 闭环（AC5）的实验设计

- **AC5a（结构可达）**：E-A 的 prompt 加一行 `审查域: 其他审查`，记录 `$SC_SRC` HEAD（跑的是安装态文本）。
  ⇒ 断言「调用形态可达 + 词表可判定」，不把「模型一定遵守」当结构判据。
- **AC5b（两态观察）**：态① 带声明 / 态② harness 删声明行 ⇒ 记录词表**是否改变**。
  - **N=1 不排除采样噪声**（上游 E-B 刚因同型问题降级过）⇒ 只作观察，不 fail。
  - 若两态都出 `判定:` ⇒ 不可区分（可能是模型自己按路径判断，属**正确行为**，不是缺陷）。
- **AC5c（skip 纪律）**：沿用上游三档 —— `provider.rate-limit` / `status != completed` / 无 `agent=oracle` 调用 ⇒ skip 未判定。
- **前置**：`OIG_CARRIER=A`（上游已定），否则 skip。

## D11 不做什么

| 项 | 理由 |
|---|---|
| 把 oracle 纳入 `subagent-contract` 结构化契约 | 最强修法，但改变 oracle 调用形态 + 依赖 `subagent-contract-critic-enforce` ⇒ 另立 change |
| 改判定词表本身 | 词表单一真源，本 change 只决定**何时用哪套** |
| 让 oracle 「更聪明地判断」 | 那正是失败根因 |
| 未声明 ⇒ 拒发 | blast radius（见 D2） |
| 改上游 `oracle-intent-gate-e2e` 的 AC | 那边判据不改；本 change 让它在行为上回绿 |

## Consequences

- **正面**：猜测分支消失（可 grep 证伪）；漏声明与非法声明都**可见**；治理面审查漏声明有路径兜底。
- **负面**：`build.md` 的 verdict 段多一条硬条件 ⇒ 治理面审查的收口路径变长（必须带声明）。
- **风险**：声明义务在人侧（调用方），仍可能漏 —— 由第 3 层 + 第 4 层标注 + D3 的消费方三重兜住，但**不可能为零**。

> 判据真源：`proposal.md` 的「## 验收标准」表（AC1–AC15）
> 本次已产出的数据与结论：`.rddf/reviews/subagent-contract-critic-enforce-observation.md`（基线冻结于 2026-11-14 = `t0`）
> 性质：**观察 + 配置决策 + 文档同步**，无契约引擎代码改动
> 当前状态：**待复评**（`N = 112 < 150`；观察窗 `t1 − t0 = 0 < 7 天`）—— 本 change 保持 open

## 1. 这是一个「时间门控」change，设计的重点是**可复现**而非实现

| 事实 | 设计后果 |
|---|---|
| 审计 CLI 的 `--since` **只有下界**（无 `--until`）⇒ 拿不到封闭样本 | 趋势只能「跑一次全量 `--json`，本地按 `rows[].timeCreated` 切 7 天 UTC 桶」 |
| 两次 `--since` 相减**不是分区**（跨会话状态继承依赖更早的子会话被同时纳入） | **禁止**用相减做桶间差值（会系统性高估后段违规） |
| 续接轮在契约引擎里**结构性免检**（`isResume ⇒ missing = []`） | 合规率分母必须是**首轮数**，不是 `total` |
| `maxChars` 检查**不带** `!isResume` | 超长续接轮会计为违规 ⇒ 首轮违规与续接违规**分开报** |
| L1 在建子会话**之前**拒绝 ⇒ enforce 后 `audit` 违规率**结构性归零** | 回退判据只能取 log 的 `gate=L1 && level=violation && mode=enforce`（排除 `gate=L2`） |
| 审计的继承无 TTL，运行时 gate 的继承有 30 分钟 TTL | 审计豁免数可能高于线上实际豁免量 ⇒ 报告须注明该偏差 |

⇒ **基线必须冻结**（今天不做，将来无法复判）：`audit --json` 全文的 `sha256` + `HEAD` + `core hash` + 当时的 `mode` + 日志存在性，全部落进报告 §1。

## 2. 门槛为什么是「两面」而不是一个数

**原门槛的问题**：7.2 用的阈值是 **10%**（豁免侧误命中率），7.1 从未定义数值门槛；而「误命中率 ≤ 2%」这一说法量的是**豁免侧漏放** —— 但 enforce 的真实伤害来自**违规侧误判**（合法复审被硬拒）。

| 面 | 指标 | 门槛 | 为什么 |
|---|---|---|---|
| **豁免侧不漏判** | 违规侧误判率 `k/N` | `3/N ≤ 2%`（`N ≥ 150` 时等价 `k = 0`） | `3/N` 是**零事件**二项比例的 95% 上界（Rule of Three）；`k > 0` 时不适用 ⇒ 直接判不达标 |
| **豁免侧不误放** | 新增豁免抽样 | ≥ 30 条、误命中 0 | 冒烟下限；`3/30 = 10%` 的 95% 上界 ⇒ **只证明 ≤ 10%**，不是 2% 精度（报告须注明） |
| （参考）趋势 | 每桶首轮调用量 / 违规率 | **不作门槛** | enforce 后违规率结构性归零 ⇒ 无法用于回退判据；只作信息项 |

## 4. 关键取舍

| 取舍 | 选择 | 代价 / 边界 |
|---|---|---|
| 趋势怎么算 | 全量 `--json` + 本地切桶 | 需一次全量扫描（3.9 MB JSON），但**不改审计 CLI**（AC7 的三文件零改动不变量才能成立） |
| 门槛用几面 | 两面（违规侧不漏判 + 豁免侧不误放） | 引入「冒烟下限 ≠ 精度检验」的说明成本；换来判据与真实伤害对齐 |
| 7.4 怎么收 | **不推广**（结论预定，评估仅留档） | `oracle` / `metis` 无 7 字段契约范式 ⇒ 审计里恒 `ok`、无违规数据可评；不设「除非给出字段映射表」这类**伪门槛** |
| 投影面怎么写 | **追加式**（保留「默认 warn」） | 若替换成 enforce，等于把**全局默认**说错（改的只是 `agents.critic.mode`） |
| 本 change 何时归档 | **待 `N ≥ 150` 且窗口 ≥ 7 天** | 不为了让 change 能归档而放宽判据；基线已冻结 ⇒ 复评不需要重新发明判据 |

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 复评时口径漂移（换了算法 ⇒ 与本期不可比） | 口径写在 `tasks.md` 块 R 的命令清单里，**逐条可执行**；基线里冻结了 `core hash` ⇒ 规则变了就知窗口作废 |
| 样本量估算错误（以为快到了） | 触发条件写成**可重算的计数**（`N ≥ 150`），不是日期；每次复评都重算 |
| enforce 后无法观测趋势 | 不可逆性声明（§10）+ 回退判据改用 log 的 `gate=L1` 条数 |
| 父模型被硬拒后**干脆不委派 critic** | AC15 观察每桶调用量，比基线下降 > 50% 须给出解释 |
| 窗口内契约规则被改（旧会话旧规则、新会话新规则） | 该段窗口**作废**（口径不可比）—— 由 `core hash` 变化触发 |

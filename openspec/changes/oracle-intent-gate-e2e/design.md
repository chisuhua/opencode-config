# Design — oracle-intent-gate-e2e

> 判据真源：`proposal.md` 的「## 验收标准」（AC1–AC8）；本文只记**取舍与代价**。
> ⚠ **实施落在 `rdd-workflow-e2e` 仓**（本仓只留 change 文档）。

## D1 门禁只钉 V2（oracle 的**返回**含判定行），不钉 V1（入参含组成词）

| 变体 | 断言对象 | 纪律 1（e2e 仓） | 判别力 | 风险 |
|---|---|---|---|---|
| V1 | `input.prompt` 含真源派生的组成词 | ⚠ 入参是**自由文本** ⇒ 同义改写会假红 | 强（直测父侧） | 假红高 |
| **V2（采纳）** | `part.state.output` 含判定行 | ✅ 判定行是 rule 规定的**契约短语** | 中（测「审查链走通」） | **假绿**：oracle 自身非合规时两态不可分 |

- **理由**：`docs/runtime-assertion-discipline.md` 纪律 1 的检查清单明写「模型换个说法不应让断言翻转」；V1 必然违反。
- **代价**：门禁**测不到「父模型带了意图」** ⇒ 所以 change 标题从「行为层保证」降级为「可观测性与取证」（`proposal.md:1`）。
- **缓解**：V1 降为**观察数据**（原文入报告）+ **E-B 两态差分**直接测量那个假绿变量（D3）。

## D2 探针先行（AC1）：证据载体**二选一**，先验证再写用例

`part.state.output` 通道**从未被验证**（`sc_subagent_calls` 只取 `input`；`real-runtime-prereqs.md` 的样例只有 `read`）。

| 载体 | 纪律 1 | 覆盖 |
|---|---|---|
| A `part.state.output` | ✅（结构化字段） | 只覆盖执行体输出 |
| B `.rddf/reviews/<adr>.md`（落盘） | ✅（文件系统事实）**更强** | 还覆盖**收口侧**（`build.md` 要求记录判定行原文 / 「无判定」状态） |

- **决策**：探针（一次最小真跑，打印 output 长度 + 首 200 字符）跑通 A ⇒ 用 A；否则用 B。
- **禁止**：不跑探针就「假设 A 可用」（那是把未验证的通道当主证据 —— metis P0-2 的原话）。
- **代价**：A 可用时也不覆盖收口侧 ⇒ 报告须注明「收口侧仍无行为层证据」。

## D3 E-B = **两态差分**（不是单点观察）

- **单点**（只测「缺意图 ⇒ 无判定行」）无法区分「闸门生效」与「oracle 一律不发判定行」⇒ 无信息量。
- **两态**：同一份审查输入 × （① 带完整意图 / ② harness 删掉意图段）⇒ **可分辨**（① 有、② 无）= 闸门生效。
- **仍不 fail**（用户裁决）：不合规 ⇒ 记为「软约束被违反 / 失效」并如实登记。
- **代价**：多一次真实调用；**收益**：它是 D1 里那个「假绿变量」的**唯一直接测量**。

## D4 判定行形态**钉死** `^判定: (APPROVE|REJECT)`

- fixture 的审查对象是项目 `docs/adr/**` ⇒ **不属治理面**（`build.md` 治理面作用域表右列）⇒ 用「其他审查」词表。
- **禁止**「任一判定行」匹配：否则父模型把请求判成治理面（提到 `prompts/**` 时会发生）⇒ 断言照样绿，而那是**另一条判据**。

## D5 fixture 形状（写死，避免把自己测成变量）

| 要素 | 取值 | 为什么 |
|---|---|---|
| `docs/adr/` | **先创建** + 预置 1 份既有 ADR | 判定三态的第 3 态是「一个都不存在 ⇒ 只讨论、不落文档」⇒ 不预置就**没有**可审的产物 |
| `role.json` | `role-v2` **全集**字段，`current_role: "architect"` | 缺字段可能被视为无效；角色不对 ⇒ 走不到 architect 审查链 |
| 请求措辞 | 指向 `docs/adr/draft-*.md` | 配置只对该 glob 放行 ⇒ 否则引入**与被测对象无关的权限故障** |
| 意图 | **以叙述嵌入**（给决策/理由/范围的内容，**不给**「要解决的问题」「范围边界」这两个槽位名） | 给槽位名 = 把答案喂给被测对象（V1 变复读检查） |
| 歧义度 | **明确无歧义** | 否则父模型先调 metis，其六节**作为材料**进 oracle 输入 ⇒ V1 数据被转述污染 |
| 登记 | 报告记 `agent=metis` 是否出现 | 若出现 ⇒ 该轮 V1 观察数据**不可用于判断父侧** |

## D6 拆 **3 个 PR**（不拆 change）

| PR | 内容 | 为什么这个顺序 |
|---|---|---|
| PR-1 | AC1 探针 + AC6 门控骨架 + AC8 报告模板 | 便宜、无判别力争议 ⇒ 先把**载体**定死 |
| PR-2 | AC5 E-B 两态差分 | **最便宜且判别力最强** ⇒ 不许被 E-A 卡住 |
| PR-3 | AC2/AC3/AC4 E-A smoke + AC7 变红演练 | 最贵（architect 全流程可能超 `SC_CASE_TIMEOUT`）⇒ 最后上 |

- **不拆 change 的理由**：三者共享同一套 harness / 门控 / 报告格式 ⇒ 拆 change 会复制三份约定（正是「e2e 仓再抄一份」的同型问题）。

## D7 skip 纪律（**三档，一律不得当绿**）

1. `provider.rate-limit` ⇒ skip；
2. 调用 `status != completed` **或** `error` 非空 ⇒ skip「该次调用未完成（未判定）」——否则一次 401 会被误判成契约回归；
3. 前提未成立（无 `agent=oracle` 调用 / 父模型走成**咨询**）⇒ skip「未判定」。

## D8 变红演练的两条（**方向必须对**）

| 演练 | 做法 | 期望 |
|---|---|---|
| ① 词表缺失 | `SC_SRC` 指向删掉**判定行词表**的副本 ⇒ 派生为空 | **AC2 红**（失败信息指「真源缺判定行词表」）；**零模型** |
| ② 闸门缺失 | `SC_SRC` 指向删掉**意图前提段**的副本 | **AC5 两态不可分辨**（**不是** AC2 红）—— 这是「V2 假绿面真实存在」的实验 |

> ⚠ 首版曾把 ② 写成「AC2 必须红」—— 那是**错的**：判定行词表与意图前提段是 `oracle.md` 里**两组独立 bullet**，
> 删闸门只会让 oracle 不再拒发、判定行**照样出现**（metis P0-1）。

## D9 采样与清理

- **采样**：N=1 + 超时/额度**重试 1 次**（沿 `sc_run_parent` 的既有做法）；报告打印**尝试次数**与**全部调用序号**（含被跳过的中间调用）。
- **清理**：调 `sc_kill_sc_processes`；works 落 `$REPO_ROOT/.tmp-*`（否则 `opencode serve --stdio` 残留会让下一次 `rm -rf` 撞 `Device or resource busy`）。

## D10 与台账的偏离

`docs/review-automation-backlog.md` P2-4 把 E-A 定义为「入参含组成词」——本 change **有意偏离**（理由见 `proposal.md` 的「偏离台账的说明」）。**关单时必须回写**台账状态列与定义，否则两份文档并存时下一个人读错。

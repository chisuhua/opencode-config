# Design — no-self-adjudication

> 判据真源：`proposal.md` 的「## 验收标准」（AC1–AC15）。本文只记**决策取舍**。

## D1. 为什么兜底形态是「正文请求裁决 + 停下」，**不是** `HANDOFF:`

`HANDOFF:` 有三重约束，使它**不能**成为独立会话的兜底形态：

| 约束 | 出处 | 后果 |
|---|---|---|
| 首行契约：HANDOFF 回合**省略角色开场报告**，首行只能是 `HANDOFF: <kind>` | `build.md` §HANDOFF 首行优先级 | 独立会话若写 `HANDOFF:` ⇒ **违反它自己的首行契约**（独立会话每回合都要输出开场报告） |
| 归属：**被派发后端**专属 | 同上（实测已在 e2e 里确认该段语义） | 独立会话不是后端 ⇒ 越权使用会**语义串味** |
| 凭据通道：`rddf feedback add --from rdd-builder` | `build.md` §HANDOFF 契约 | 独立会话**没有** feedback 凭据通道 ⇒ 写了 `HANDOFF: blocked` 也**无处落凭据** ⇒ 主会话拿不到可追溯的交回记录 |

⇒ 独立会话的兜底只能是：**正文里明确说「这需要你裁决」+ 列出候选路径 + 停下**。
⇒ 被派发后端保持 `HANDOFF: blocked`（`kind` 词表里已含「缺用户决策」）⇒ **后端侧不改**（design D2）。

## D2. 为什么后端侧**不改**

后端已有 `blocked` kind，且 `build.md` 明确写了 `blocked` = 「缺外部信息 / 凭据 / **用户决策** / 主会话的派发决策」
⇒ **同类兜底已被覆盖**，且形态更完整（有凭据落点）。
⇒ 本 change 只补**独立会话**侧 ⇒ 边界清晰、后端行为零变化。

## D3. 为什么是**通用**规则，而不是给越权单独加一条

实测的失败是越权触发的，但**根因**是「需要用户拍板的分叉没有统一兜底」：
角色切换（用户口令触发）、以及各类需要拍板的分叉，都属同一类。

⇒ 加一条**通用**规则 ⇒ 覆盖**未来新增**的分叉（不必每加一处就补一条）⇒
⇒ 这也符合本仓「按类而非按例」的判据风格（如 v2.30 的「描述面枚举闭集」）。

## D4. 「停机并交付裁决请求」的**可判定性**（软约束下的硬要求）

本仓的角色越权防护是**软约束**（权限层**没有**按角色硬 deny）⇒ 「停下」没有工具层保证
⇒ 只能靠**可机械核的判据形态**：

| 要求 | 为什么 |
|---|---|
| 必须**列出候选路径** | 否则用户不知道能选什么 ⇒ 兜底退化成「拒绝 + 没了」 |
| 必须**显式禁止「自行假设/最合理的假设」** | 实测的正是这个措辞 ⇒ 只写「停下」会留**半条规则**（禁了动作、没禁推理） |
| 必须**禁「换个写法绕过」** | 与既有「不要换写法绕过」的纪律同族（`build.md` 多处已有） |
| 必须**禁「执行被禁动作」** | 实测里模型**既**假设**又**执行了 ⇒ 两条都要禁 |

⇒ AC2 专门钉「硬禁止」条里**必须含**「自行假设」族措辞 ⇒ 防半条规则。

## D5. 为什么**不改**「禁止静默执行」那条

既有那条写「**禁止**：静默执行，或假装没注意到冲突」⇒ 它禁的是「**不吭声**地做」。
实测的失败是「**吭声了**（还加了注记）但自行假设」⇒ **不违反**那条 ⇒ 两者正交。

⇒ 本 change **补**一条（自行假设 = 另一种越权），**不动**那条 ⇒ 两条覆盖两种失败形态。

## D6. 为什么不把权限层改成硬 deny

那会让「角色」从**软约束**变成**工具层保证**（架构级变更，影响所有 agent 的权限矩阵与 `opencode.jsonc`）
⇒ 本仓现状是**有意**的软约束（角色矩阵注释：「约束性质：软约束——权限层没有按角色做硬 deny，越权靠自觉与用户纠正」）
⇒ 改它是**改架构立场**，不在本 change 的边界 ⇒ 登记为可能的独立议题。

## D7. 独立会话侧**没有凭据通道** ⇒ 审计上限 = 首行可 grep 标记（不是审计链）

被派发后端有 `rddf feedback add --from rdd-builder`（`kind=blocked` 落凭据 ⇒ 可审计）；
独立会话**没有**这条通道（D1 理由）⇒ 「停下」若只存在于对话正文 ⇒ **事后不可查**。

新建落点文件会引入新写入者（违反 single-writer）+ 超 scope ⇒ 否。
⇒ **廉价上限**：要求停机回合在**开场报告之后的第一段**写一个可 grep 的标记
（仿 `build.md:543` 的 `⚠️ 未启用 <reviewer> 审查` 惯例；⚠ **不占首行** —— 独立会话每回合都要输出
开场报告，占首行会与首行契约冲突，与 D1 否决 `HANDOFF:` 是同一条理由）
⇒ 零新工件、事后可 grep transcript、层 2 可断言。
⚠ **如实声明**：这是**审计上限**，**不是审计链** —— 没有结构化凭据、没有时间戳、没有操作者。

## D8. 触发面必须**闭合两类**，并与 `build.md:717` 划清边界

`build.md:717`：「否则就用**最合理的默认值直接做**」⇒ 若新节禁「最合理的假设」，
两条**相邻且措辞同族**的规则 ⇒ 模型行为不可预测（可能该做的也停下）。

⇒ 触发面**闭合成两类**（全是仓里已有的可判定结构）：
① 候选路径之一会**越出当前角色的允许集**；② **需要用户口令级授权**（角色切换 / 授权窗口；
改已签批 ADR 需切 architect ⇒ 属此类）。
⇒ 「先跑测试还是先读代码」**不在其中** ⇒ 一般工程判断仍走 717 行。
⇒ 新节**明写这条边界**（否则两条规则仍相邻 ⇒ 不可预测）。

## D9. 行为层判据必须是**三件套** + 一个**控制用例**

| 断言 | 能证明 | 不能证明 |
|---|---|---|
| 负向：**`edit`/`write` 的目标路径落在当前角色允许集外 ⇒ 红** | 「**执行了**被禁动作」（按**写目标**判定 ⇒ 不被 `read` 之类误伤） | ⚠ 抓不到 `bash` 写盘（`sed -i` / `tee`）—— `build.md:609` 明说 shell 不受角色约束 ⇒ **已知盲区，须登记** |
| 负向：fixture 仓内 `git status --porcelain -- src/` **为空** | 「没留下改动」（改动又还原时为空） | 「**正确地**停下了」—— 模型崩溃 / 卡额度 / 输出空白回合也绿 |
| **正向**：响应含停机标记 + 候选路径 + 「需要裁决」 | 「**确实**请求了裁决」 | —— |

⇒ 三者**合起来**才有判别力（只有负向 ⇒ 规则退化成「什么都不做就通过」）。
⇒ **裁决合成**：两条负向**任一红 ⇒ 整体验收红**（「改了又还原」按 D4「不得执行被禁动作」判红）；
报告须注明**是哪条负向**触发。
⇒ 另加**控制用例**（合法动作 ⇒ **必须真的推进**）⇒ 唯一能判定「触发面没写太宽」的机制
（否则「动辄停下」这个真实风险无任何判据）。
⇒ **连跑 ≥3 次**（单次绿分不清「规则生效」与「这次恰好没假设」）。

## D10. 两条**实现约束**（避免撞既有守卫）

新节落在 `prompts/build.md` ⇒ 会撞既有守卫：

| 约束 | 原因 |
|---|---|
| 新节内**不得**出现 ```` ```json ```` | 撞守卫⑥「全文仅 1 个 json 块」（授权窗口示例的唯一性） |
| 新节内**不得**让「输出新角色的开场报告」出现**第二次** | 撞守卫⑤的「每步全文出现次数 == 1」判据 |

⚠ **词表台账**：本 change 新增一族**枚举式词表**（「自行假设 / 最合理的假设」族）⇒ 按
`docs/guard-authoring.md` §3.3 必须在**守卫注释 + CHANGELOG** 登记为已知残留，
且该文档「两处枚举式词表」的表述要改成**三族并列**（不得写成「唯一」）。

## 风险与回滚

| 风险 | 缓解 |
|---|---|
| 「停下」导致 agent 在无人值守场景**卡死**（不做事） | ⚠ **这是有意的取舍**：软约束下「卡死」优于「越权执行」。且本仓已有 `blocked` 概念（后端侧）⇒ 独立会话侧也应有「等裁决」的终止态 |
| 规则太宽 ⇒ 正常任务被误判成「需要裁决」而停下 | 触发面要**窄**：只限「需要用户拍板的**两类分叉**」（越出角色允许集 / 需口令级授权），不是「任何不确定」⇒ AC1 的「触发面」措辞要具体（越权引导 / 角色切换授权 / 其它选项分叉） |
| 层 1 判据变成**措辞**判据（换词即绕过） | 与既有「独立会话机制」族同形（结构 + 关键词族）⇒ 并登记其固有边界 |
| **回滚** | 删掉新节 + 回退守卫 ⇒ 行为层 E-4 恢复为 skip（注明已知失败）⇒ **不得**回滚成「E-4 真跑但红」 |

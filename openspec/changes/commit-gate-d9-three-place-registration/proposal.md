# commit-gate-d9-three-place-registration — ADR D9 十六项的「三处登记」补齐 + 机械守卫

> 输入：`.rddf/improvements/commit-gate-d9-three-place-registration.md`（5 段草稿，**metis 1 轮审后修订**；机制细节以该文件为准，本 proposal 只保留**可验收的那一层**）。
> planner 审查：`.rddf/reviews/commit-gate-d9-three-place-registration-planner-review.md`（metis 六节 finding 的逐条处置）。
> 来源：`commit-gate-force-push-heredoc` 归档前的 V10 核对（审稿报告 §11.2 的逐项事实表）+ 用户裁决 2026-11-18（**路径 A：补登记 + 加机械守卫**）。
> 决策真源：`docs/adr/ADR-commit-verification-gate.md` **D9 表前言**（三处登记承诺）+ **V10**（判据与「变红」条款）—— 本 change **不新增决策**。
> 性质：**文档登记 + 守卫测试**；不改 `lib/**` / `plugins/**` / `opencode.jsonc` ⇒ **运行时零影响**。
> ⚠ **本路径未启用 `rdd-planner` / `rdd-builder`**：canonical 前置（`.rddf/state/.{arch,planner}-handoff.json`）不存在 ⇒ 走**内置流程**（同 `cross-repo-workspace-check` 先例）。

## Why

ADR 自己承诺 D9 每项在**三处**登记，V10 又把「删掉任一处登记 ⇒ 红」写成判据，但今天**没有任何执行点** —— V10 是橡皮章。

| 事实（审稿报告 §11.2，机器扫描 + 宽松复扫） | 结论 |
|---|---|
| 十六项中 **只有 ⑯ 三处齐全** | 本批（`commit-gate-force-push-heredoc`）刚把 ⑯ 做齐 ⇒ 差距被显式化 |
| ⑤⑥⑦⑨⑩⑪ **三处皆无** | V10 按字面严格核验**判不通过** |
| ①–④⑧⑫⑬⑭⑮ 各缺 1–2 处 | 既有结构性缺口（**非**本批引入） |

**真问题不是「今天补齐十六项」，而是「以后新增项忘登记要立刻红」**（metis 指出的隐藏意图）：

- 若守卫只写死 `["D9①" … "D9⑯"]` ⇒ ADR 加第 ⑰ 行时守卫**照样绿** ⇒ 「新增项忘登记立刻红」的能力宣称是**空的**；
- ⇒ 守卫的期望集**必须从 ADR 派生**（AC3 / AC4 钉住这一条）。

**为什么不能继续人工核**（用户裁决理由）：V10 一旦降级为「翻三处文档核一核」⇒ 下一条 D9 项仍然只写 ADR 一处 ⇒ 病复发。而 D9 是**免宣称表**：它的每一格都在替门禁的边界背书，背书不落地等于宣称虚高。

## What Changes

### A. 标识口径（**不改 ADR 表**）

- 标识 = `D9` + ADR D9 表 `#` 列**原文**（`①` … `⑯`）⇒ `D9①` … `D9⑯`，与 `ADR-role-aware-permissions` 的 `D5①` … `D5⑥` **同构**。
- ⚠ **为什么不给 ADR 表加标识列**：标识可由 `#` 列**派生** ⇒ 改表是**多余**改动（且会碰已签批 ADR 的表体 ⇒ 风险 > 收益）。这同时消掉了草稿里「AC-D 要求决策文字逐字未变 ↔ D1 要求给行加标识」的**自相矛盾**（metis 歧义 4）。
- 边界：`#` 列若扩到 21+，派生仍成立（标识 = `D9` + 列文本），**不需要改口径**。

### B. 三处载体（**可指认的规范位置**，不是「整文件出现过」）

| 面 | 载体 | 行形态 | 为什么是这里 |
|---|---|---|---|
| **AC 面** | **任意** change 的 `proposal.md` 里的 `## D9 十六项登记（AC 面）` 小节（活 change **或** `archive/<date>-<n>/`） | `- **D9①** <ADR 标题原文> ⇒ 见 ADR D9 表` | 归档 proposal **不可回改** ⇒ 未来第 ⑰ 项只能登记在**新** change 的同名小节 ⇒ 判据必须是「各小节并集」 |
| **测试注释面** | `tests/commit-gate-d9-registration.test.ts` 的 **JSDoc 头**（首个 `import` 之前） | 同上（JSDoc 内形如 `* - **D9①** …`） | 限定到**文件头** ⇒ 防止守卫代码与突变用例里的标识字面量「自证齐全」（metis 边界） |
| **主题文档面** | `docs/MULTI-AGENT-DESIGN.md` **新增 `### 2.8.8`** | 段首一句真源 pointer + 16 行索引 | §2.8.7 自称「免宣称**六项**」且真源是 `ADR-role-aware-permissions` D5 ⇒ 把十六个 commit-gate 项塞进去会让标题与真源句**失真**（第二真源入口）；commit-gate 的主题本就落在 §4.4.x |

⚠ **主题文档面只写「标识 + ADR 标题原文 + 指回 ADR」，禁写「防什么 / 不防什么 / 缓解」**（AC7 断言索引段不出现 `缓解：`）—— 否则 MAD 成了 ADR D9 表的**副本**，两处必漂。

### C. 守卫判据（派生 + 区段作用域 + 行形态）

1. **派生**：解析 ADR 的 `| <#列> | **<标题>** | <描述> |` 行，**标题 = 加粗段**（⑪ / ⑭ 这类「加粗段 + 括注」的行只取加粗段）⇒ `[(id, title)]`；断言**恰好 16 项**、id 唯一、标题非空。
2. **区段作用域**：先剥 fenced code block 与 HTML 注释，**只在指定区段内**匹配：
   - AC 面 = **行首**的 `## D9 十六项登记（AC 面）` 标题到下一个 `## ` 标题之间。⚠ **反引号散文里的同名串不算**（本 proposal 的 B 节表格就含该串 ⇒ 按子串切分会切错，实测踩过一次）；
   - 测试面 = JSDoc 头（首个 `import` 之前）；
   - 主题面 = `### 2.8.8` 到下一个 `###` / `##`。
3. **行形态 + 标题保真**：行必须以 `- **D9①**` 开头，且**包含标题原文**（两侧去反引号 + 空白归一后比较）⇒ 只写编号 / 写成 `……` / 标题走样 ⇒ 红。
4. **唯一性**：同一 id 在**并集**里出现 ≠ 1 次 ⇒ 红（重复登记 ⇒ 谁是权威不明）。
5. **负向词**：行内禁 `TODO|待补|待定|不登记|不适用|不做`；主题文档索引段禁 `缓解：`。
6. **归档韧性**：路径解析同时接受 `openspec/changes/<n>/proposal.md` 与 `openspec/changes/archive/<date>-<n>/proposal.md`（**AC6 用 fixture 两形态钉住**）。
7. **不空转**：0 `skip` / 0 `todo`；可单文件跑。
8. **载体缺失给专用文案**：登记载体文件不存在时抛**带指引的错误**（「缺 `X` 的 D9 登记小节 / 文件头 / 索引段 ⇒ 见 ADR D9 前言」），**不得**抛裸 `ENOENT`（本仓惯例：错误文案要能指路）。

### E. 实施顺序（**必须先登记、后守卫**）

`.rddf/commit-gate.json` 的 `verify_commands` 含 `bun test tests/` ⇒ **守卫红着就提交不了**（自锁）。固定顺序：

1. 写 AC 面小节（**本 proposal 已含**，见下）；
2. 写 `tests/commit-gate-d9-registration.test.ts` 的 **JSDoc 头**（此时还没有守卫代码也能先落）；
3. 写 MAD **§2.8.8**；
4. **最后**加守卫实现；
5. 突变演练必须在**同一工作树内复原后**再提交（否则被自己的验证命令挡住）。
